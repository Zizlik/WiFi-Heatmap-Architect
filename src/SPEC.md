# WiFi Heatmap Architect v3 — product & engineering spec

Rewrite of a single-file Wi-Fi coverage planner. Goal from the user (Czech, verbatim intent):
**"Make a completely better design of the whole app — as intuitive and as simple as possible, use shortcuts and tiny
question-mark hints that show a tooltip explaining what a thing is. Right now the app doesn't even work properly."**

The previous version (kept for reference in `../puvodni-verze/index.cs.html`, **never edit it**) is a patch-on-patch pile:
4 wizard steps + a reference tab, hidden "legacy" controls moved around by script, a rigid 180×157 occupancy grid,
ray-casting artifacts (wedge/stair-step banding in the heat map), an explicit "Apply floor plan" step, English
demo names in the Czech UI, ASUS-specific copy although the user owns a Ubiquiti router. We rewrite it from scratch,
**keeping all capabilities and file-format compatibility**, but with a far simpler UI.

Audience: a non-technical home user (Czech first, English second). Tone: friendly, plain language, "ty" form in Czech.

---------------------------------------------------------------------------------------------------------------------

## 0. Hard constraints

1. **Deliverable = two self-contained static files**: `index.cs.html` (Czech default) and `index.html` (English default),
   both generated by `node build.mjs` from `src/`. They are *the same app* (same code, both languages inside, runtime
   language switch); only `<html lang>` and the default language differ. Must work by **double-clicking the file
   (`file://`)** — no network, no fetch of local files, no ES modules, no CDN, no external fonts/images. Everything inline.
2. Plain browser JS (ES2022, evergreen Chrome/Edge/Firefox/Safari 16+), no frameworks, no build-time transpiling.
   All source files are classic scripts concatenated in lexical path order into ONE `<script>`; each file is an IIFE
   that attaches to the global namespace `window.WH` (use `globalThis` so engine files also load in Node tests).
   Never emit the text `</script` inside JS.
3. **File-format compatibility.** The SVG project files written by the old app (`format: "wifi-floor-v2"`, see §3.2)
   MUST load, including real user plans with a PNG tracing background (a private real plan is used for testing; it is
   never part of the repository - see `WH_PRIVATE_PLAN` in ENGINE-API §11). Files we write must stay loadable by the OLD app too
   (keep `format:"wifi-floor-v2"`, keep the old top-level keys `plan,width,router,original,optic`; extra keys are ignored by it).
4. Old localStorage keys (`wifi-floor-v5`, `wifi-floor-network-v1`, `wifi-speed-v1`, `wifi-flow-v1`) are migrated once
   into the new project if the new key is absent (best-effort, never throw).
5. Calculations are local; nothing is sent anywhere. Keep the footer claim true.
6. Czech and English are both complete — every user-visible string goes through `WH.i18n.t()`; no hard-coded text in JS/HTML
   (HTML uses `data-i18n*` attributes). Missing key must fall back to the other language, then to the key (and `console.warn` once).
7. Accessibility baseline: real `<button>`s, visible focus ring, labels for inputs, `aria-live` for results, keyboard
   operation for every action (including moving markers with arrow keys), `prefers-reduced-motion`, contrast ≥ 4.5:1,
   `prefers-color-scheme` dark mode + manual theme switch.
8. Performance: dragging the router must feel instant (≥ 30 fps) on a 12 m flat with ~20 walls and ~20 furniture
   polygons; a full-quality recompute ≤ 150 ms on a laptop. Use a coarse raster while dragging, refine after ~120 ms idle.
9. Robustness: never throw to the console during normal use; corrupt files/localStorage → friendly toast, app stays usable.
10. Size: each built file ≤ 2.5 MB without a user background image (`node build.mjs --check` enforces it; raised from 1 MB in
    stage 5 (the stage-4 bundle was ~977 KB), from 1.5 MB in stage 7 (the stage-6 bundle was ~1408 KB) and from 2 MB in
    stage 9 (scale, many nodes and floors brought the bundle to ~2.0 MB)). The bundle is deliberately NOT minified: readable
    code is worth more than bytes for a local app opened from disk (GitHub Pages serves it gzipped, ~570 KB on the wire).

## 1. UX design

### 1.1 Principles
1. **One question per screen**: *"Where is my signal good, and where should the router go?"*
2. **Zero-config start**: demo flat or own plan → a heat map is visible within 10 seconds, no wizard.
3. **Live everywhere**: there is NO "apply floor plan" step. Plan edits are instantly reflected in the Wi-Fi view.
4. **Progressive disclosure**: the basics are always visible; everything technical lives in collapsed "Pokročilé / Advanced".
5. **Everything explains itself**: each non-obvious label has a tiny round **"?"** hint (hover/focus/tap → popover with a
   plain-language explanation); every icon button has a tooltip including its **keyboard shortcut** (`<kbd>`).
6. **Honest**: a persistent "Orientační odhad / Approximate estimate" badge (with a "?" hint). Calibration with measurements
   is encouraged but optional.
7. Never block: no modal dialogs for normal work (only: welcome, shortcuts sheet, help, confirm-destructive).

### 1.2 Information architecture
Two top-level modes (header segmented control; shortcut `1` / `2`):
- **Půdorys / Floor plan** (editor) — draw/import/adjust the plan.
- **Wi-Fi** (planner) — see coverage, move the router, find the best spot, add measurements.

First run (no saved project): full-screen **Welcome** overlay with three big cards + a drop zone:
(1) "Vyzkoušet ukázkový byt / Try the demo flat", (2) "Nahrát můj půdorys / Load my floor plan" (SVG saved from this app,
or PNG/JPG/WebP/SVG image to trace), (3) "Nakreslit od nuly / Draw from scratch". Dropping a file anywhere on the page imports it.
After a project exists the app reopens straight in **Wi-Fi** mode with the last project (autosaved).

### 1.3 Header (56 px, sticky)
`[logo + "WiFi Heatmap Architect" (+ tiny subtitle)] [mode switch: Půdorys | Wi-Fi] … [estimate badge ?] [Soubor ▾] [⌨] [◐ theme] [CS|EN] [? Nápověda]`
- **Soubor / File ▾** menu: Otevřít soubor… (`Ctrl+O`), Uložit projekt jako SVG (`Ctrl+S`), Uložit půdorys jako PNG,
  Uložit mapu signálu jako PNG (planner), —, Ukázkový byt, Nový prázdný plán (both confirm if the plan is non-trivial), —,
  Smazat uložená data v tomto prohlížeči (confirm).
- **⌨** opens the shortcut cheat-sheet (also key `?`).
- **? Nápověda** opens Help panel: "Jak to funguje" (3 short steps), "Spustit prohlídku", "Jak změřit signál" (platform tips,
  see §1.9), "Slovníček" (auto-generated list of every `help.*` entry), "O modelu" (illustrative model, links: ITU-R P.1238, Cisco
  Wi-Fi throughput testing), and the footer line "Výpočty probíhají v tomto prohlížeči…".

### 1.4 Wi-Fi mode (planner) layout
Desktop: `[ map stage (flex 1) | sidebar 360 px ]`. < 900 px: sidebar goes below the map (map first). Stage height fills the viewport
(no page scroll needed to see the whole map on a 1366×768 laptop).

**Map stage** (canvas for static drawing + DOM/SVG markers; pan with drag on empty space/middle button/space-drag, wheel/pinch zoom,
`+ − 0` keys; zoom buttons bottom-right; double-click empty space = fit):
- top-left: **view switch** `Signál | Rychlost | Změna proti dnešku` (Signal | Speed | Change vs today) with "?" hint;
- top-right: **band switch** `2,4 | 5 | 6 GHz` with "?" hint (explains range vs. speed trade-off);
- bottom-left: **tool palette**: `Router (R)` default pointer tool; `Měřit signál (M)`; `Vrstvy` popover (Dosah čar `L`, Zdi, Nábytek, Popisky, Hodnoty, Body měření, Předpověď u bodů `P` - SPEC 10.2);
- bottom: **legend** — gradient with word labels (Špatný … Výborný) + dBm ticks and a marker at the "good signal" threshold;
- markers (always directly draggable, keyboard-movable, no tool switch needed): **Router** (red R, "Zkušební poloha"), **Dnes** ghost (dashed ring,
  shown only when different from trial), **Internet** (inlet/modem), **Uzel 2** (only when a second node is enabled), **measurement dots**.
- hover/touch tooltip on any floor point: room, signal in dBm + quality word, Δ vs today, (speed view: predicted ↓/↑ Mb/s).
- while the optimizer runs: inline progress bar on the stage.

**Sidebar cards** (top → bottom; collapsed/expanded state remembered in prefs):
1. **Začínáme / Getting started** checklist (only until all done or dismissed): ✔ Půdorys · ✔ Kde je dnes router · ○ Zkus přesunout router · ○ (volitelně) Změř signál.
2. **Výsledek / Result** — target selector (`Celý byt` or a room) + big number *Pokrytí* ("Dnes 54 % → Zkouška 91 %", delta chip), average dBm with quality word,
   one plain sentence ("Většina bytu má dobrý signál."), and the **room list** (name, bar colored by quality, % and dBm, Δ arrow). Clicking a room row sets the target.
3. **Router** — "Zkušební poloha" status + buttons: **✨ Najít nejlepší místo (F)**, **↩ Vrátit na dnešní místo (D)**, **📍 Označit jako dnešní polohu**
   (asks to confirm and drops measurements because they belong to the old position); "Kam ho můžu dát?" select (Kamkoli / room);
   distance to internet inlet (straight line + rough cable estimate) with "?".
4. **Zpřesnit měřením / Improve with measurements** (collapsible, badge = count) — 2-sentence explanation, big button **Přidat měření (M)**,
   list (name, dBm, band, ↓/↑, edit/delete), calibration status per band ("model upraven o −6 dB, sedí na ±3 dB"), switch "Použít měření ke kalibraci".
5. **Druhý přístupový bod / Second access point** (collapsible) — scenario select (Žádný, AP po kabelu, Mesh po kabelu, Mesh přes Wi-Fi, Opakovač), bands, power, backhaul.
6. **Rychlost / Speed target** (collapsible; relevant to the Speed view) — device, target ↓/↑, reserve, internet plan limits (↓/↑), advanced link limits
   (WAN port, ONT port, negotiated link, cable category/length — all optional, one "Přípojka a kabel" sub-disclosure).
7. **Pokročilé / Advanced** (collapsed) — scale ("Skutečná šířka bytu (m)"), model parameters (signal at 1 m for 5 GHz, distance decay exponent, default wall loss,
   good-signal threshold, range-line threshold), which rooms count toward "Celý byt", color-blind palette, reset model.

### 1.5 Floor-plan mode (editor) layout
`[ tool rail (56 px, vertical icon buttons with kbd badges) | stage (flex 1) | inspector 320 px ]`, `< 900 px`: tool rail becomes a horizontal bar above the stage, inspector below.
- Tools (all with tooltip + shortcut): `V` Vybrat/posunout · `R` Obdélníková místnost · `P` Místnost po bodech · `W` Zeď · `D` Dveře/průchod · `F` Nábytek · `S` Nastavit měřítko — plus Undo/Redo, Zoom, Fit.
- Stage: SVG, pan/zoom, grid-snap toggle `G`, tracing background toggle `T`, a contextual **hint line** under the toolbar describing the next click for the active tool.
- **Inspector** (right): when nothing selected → "Půdorys" card (counts, scale line "1 m ≈ 83 px", buttons: **Obtáhnout zdi kolem místností**, Nahrát podklad k obkreslení, podklad ✓ + průhlednost, přichytávání ✓,
  Ukázkový byt, Nový prázdný plán). When an object is selected → properties: name, (wall) material select + dB, (door) "otevřený průchod 0 dB / zavřené dveře ≈ 3 dB" + width, (furniture) kind preset + dB + "blokuje signál" switch, (room) color, Delete, Duplicate.
- Primary CTA top-right of the stage: **Hotovo → Wi-Fi** (`2`). No apply step; the planner always reads the live plan.
- **Door tool**: one click on a wall places a door (default width 0.9 m = `0.9/mpp` px, centered at the click, clamped inside the wall); the door's ends are draggable along the wall.
- **Scale tool (`S`)**: click two points of a known real distance → modal-free popover asks "Kolik je to metrů?" → sets `scale.mpp`. Also a numeric "Skutečná šířka bytu (m)" in the inspector.
- **Auto-walls** (`Obtáhnout zdi kolem místností`): for every room edge not already covered by a collinear overlapping wall (tolerance 3 px), add a wall (default material), deduplicating shared edges between neighbouring rooms. Non-destructive. Also offered (checked by default) as "Přidat zdi kolem nové místnosti" when drawing a room.
- Furniture tool: pick a preset (Postel, Sedačka, Skříň, Knihovna, Lednice/pračka, Stůl, Kovová skříň, Vlastní) → drag a rectangle; preset sets attenuation (dB) and kind.
- Selection: click; drag body to move; drag white handles to reshape; double-click on an edge adds a vertex; `Alt`+click vertex removes; arrows nudge (Shift = ×4); `Delete`/`Backspace` removes; `Ctrl+D` duplicates; `Esc` deselect/cancel; rubber-band not required.
- Snapping: grid (1 % of canvas ≈ 10 px) and to existing vertices/wall endpoints within 8 screen px (visual guide). Holding `Alt` disables snapping temporarily.

### 1.6 Shortcuts (single registry, shown in the cheat sheet, mode-scoped, ignored while typing in inputs)
Global: `1` Půdorys · `2` Wi-Fi · `?` cheat sheet · `Ctrl+S` save SVG · `Ctrl+O` open · `Ctrl+Z` undo · `Ctrl+Shift+Z`/`Ctrl+Y` redo · `Esc` cancel/close · `+`/`-`/`0` zoom in/out/fit (theme only via the header button).
Wi-Fi: `R` router tool · `M` measure tool · `B` next band · `V` next view (signal→speed→change) · `L` toggle range lines · `F` find best spot · `D` router back to today's place · arrows move the router (0.25 m, `Shift` = 1 m) · `Enter` on a pending measurement saves.
Floor plan: `V R P W D F S` tools · `G` snap · `T` tracing background · `Enter` finish polygon room · `Delete` · `Ctrl+D` · arrows nudge.
Number keys `1`/`2` must not fire when a text/number input is focused.

### 1.7 Hints ("?" system)
- `WH.ui.hint(key)` → returns `<button type="button" class="hint" aria-label="…">?</button>`; declarative form in HTML: `<span data-hint="band"></span>` replaced by `WH.ui.enhance(root)`.
- Popover content from i18n: `help.<key>.t` (title), `help.<key>.b` (1–3 sentences, plain language, with a concrete example/number), optional `help.<key>.more` (second paragraph).
- Opens on hover (150 ms delay, desktop), focus, click/tap; closes on Esc/blur/outside-click/scroll; positioned to stay inside the viewport; one shared popover element; `role="tooltip"`, trigger has `aria-describedby`.
- Icon-only buttons use `data-tip="<i18n key>"` (+ optional `data-kbd="R"`) → same popover engine in "small" variant (shows label + `<kbd>`), with native `aria-label` kept.
- **Mandatory hint keys** (each in CS+EN): `estimate, dbm, quality, band, band24, band5, band6, threshold, coverage, avgSignal, target, today, trial, baseline, inlet, cable, optimize, allowedArea,
  nearSignal, decay, wallLoss, scale, calibration, measurement, residual, device, speedView, diffView, speedTarget, reserve, plan, wan, wanPort, ontPort, link, cableCategory,
  secondAp, apCable, meshCable, meshWifi, repeater, backhaul, power, ranges, rangeThreshold, wallMaterial, doorLoss, furnitureLoss, blocksSignal, snap, trace, autoWalls, roomsCount, palette, p10`.

### 1.8 Visual design
- Calm, modern, airy. Tokens as CSS custom properties on `:root`, redefined for dark (`@media (prefers-color-scheme: dark)` guarded by `:root:not([data-theme="light"])`, and `:root[data-theme="dark"]`).
  Light: bg `#f3f6fb`, surface `#fff`, ink `#13233a`, muted `#5b6a80`, line `#e2e8f1`, accent `#0f766e` (teal), accent-ink `#fff`, warn `#b45309`, danger `#c2410c`.
  Dark: bg `#0c1424`, surface `#142038`, ink `#e7eefa`, muted `#9fb0c8`, line `#24344f`, accent `#3fd0bf`, accent-ink `#06201d`.
- System font stack, 15 px base, tabular numbers for all metrics, radius 12–16 px, soft shadows, 8-pt spacing grid. No emoji in UI chrome (use inline SVG icons from `WH.ui.icon(name)`); emoji allowed only inside toasts/help copy if helpful.
- Heat palette (default): stops (dBm → RGB) `-85 [228,60,46]`, `-75 [238,109,48]`, `-65 [239,181,76]`, `-55 [183,186,71]`, `-45 [114,183,85]`, `-30 [100,174,181]`;
  color-blind palette (`cb`): `-85 [68,1,84]`, `-75 [59,82,139]`, `-65 [33,145,140]`, `-55 [94,201,98]`, `-45 [189,223,38]`, `-30 [253,231,37]`.
  Diff palette (Δ dB): `≤-10` red `[214,69,65]`, `0` neutral `[170,178,190]`(alpha lower), `≥+10` green `[46,160,110]`.
- Quality words (fixed cut-offs on dBm): ≥ −50 Výborný/Excellent · −50…−60 Velmi dobrý/Very good · −60…−67 Dobrý/Good · −67…−75 Slabý/Weak · −75…−85 Velmi slabý/Very weak · < −85 Nepoužitelný/Unusable.
- Map stage: plan area drawn on a neutral stage (light `#e9eef6` / dark `#0b1322`); heat is clipped to room polygons (crisp edges); walls dark ink, thicker for exterior/high loss; doors as gaps with small arc/teal tick; furniture as hatched low-alpha shapes; room labels with halo; markers with white ring + shadow.

### 1.8.1 Icons, SVG & alignment (user explicitly complained that icons/SVGs look broken and things are off-center)
- **No Unicode glyphs or emoji as icons** anywhere in the chrome (the old app used `◉ ↖ ▱ ▭ ━ ▰ ▧ ×` — they render inconsistently per font/OS and look broken). Every icon = inline SVG from `WH.ui.icon()`.
- Icon set rules: one consistent style — `viewBox="0 0 24 24"`, `fill="none"`, `stroke="currentColor"`, `stroke-width="1.75"` (or 2), `stroke-linecap="round"`, `stroke-linejoin="round"`; geometry optically centered in the 24×24 box with ~2 px padding (no icon touching the edge, no off-center glyph); `aria-hidden="true"` + `focusable="false"`; `display:block` (no baseline gap); rendered at 16/18/20/24 px only, `flex-shrink:0`.
- Every icon button / badge / round "?" hint / marker / kbd chip / step number must be **perfectly centered**: use `display:inline-grid; place-items:center` (or flex center) with explicit equal width/height, `line-height:1`, no padding asymmetry; text+icon buttons use `inline-flex; align-items:center; gap`. Map markers are positioned by their exact center (`translate(-50%,-50%)` of a box whose visual center = the anchor point; labels must not shift the anchor).
- The favicon and brand mark are inline SVG (no glyph), crisp at 16 px and 32 px.
- Any SVG we generate (editor stage, exported project SVG, PNG export) must be valid (XML-escaped text, correct viewBox, no NaN/undefined attributes, `vector-effect="non-scaling-stroke"` for strokes that must stay constant while zooming), and render identically in Chrome/Firefox/Safari.
- QA must include zoomed screenshots of every icon at 1× and 2× DPR in light/dark and a check that bounding boxes of icon/label pairs are vertically centered (±1 px).

### 1.9 "Jak změřit signál" (Help panel content, CS/EN)
Short, platform-specific: **Android** (WiFiman by Ubiquiti or "Wi-Fi Analyzer" → shows dBm), **iPhone** (no dBm in Settings; use the free WiFiman app), **Windows** (`netsh wlan show interfaces` → "Signal" %, convert dBm ≈ %/2 − 100 — the measurement form has a **unit toggle dBm | % (Windows)** that converts), **macOS** (Option-click the Wi-Fi menu icon → RSSI), **Linux** (`nmcli dev wifi`). Speed: fast.com / speedtest, same device, same band, note ↓ and ↑. Always measure with the device connected to the main router, second node switched off, same spot ±0.5 m, 2–3 repeats → take median.

### 2.2 Engine API (pure, DOM-free except where noted; must run under Node for tests)

### 3.3 Physics (port faithfully from old `rawPredict`, fix the artifacts)
`signal(a→b, band) = nearSignal − 20·log10(band/5) − 10·n·log10(max(1, distM)) − obstacleLoss + offset`, clamped to [−110,−20] dBm.
`obstacleLoss(a,b)`: **walls** — find ray/segment crossings; treat each wall as extended by ε≈1.5 px at both ends (closes corner gaps that caused wedge artifacts); collect `(t along ray, loss)`, sort by t, **cluster crossings closer than ≈2.5 px along the ray (corners/T-junctions/overlapping duplicate walls) and take the MAX loss within a cluster**, sum clusters. A collinear overlap ("ray runs inside a wall") counts as one crossing of that wall. A crossing lying within a door's span (distance to the door segment < 3 px) uses `door.loss` instead of the wall's. Wall loss = `wall.loss` if finite else `model.wallLoss`.
**furniture** — if `blocksSignal !== false` and the ray passes through the polygon interior, add `loss` once per piece (inside test of sub-segment midpoints between boundary crossings, bbox-culled).
~~Band does not alter wall loss (kept identical to v2 so numbers stay comparable).~~ **Superseded by §7.1 (stage 5):** every stored
obstacle loss is the 5 GHz value; presets use per-band tables, other numbers are scaled by `k = {2.4: 0.65, 5: 1, 6: 1.15}`. Second node: `signalNode = signal(node→p, band, offset + node.power)` only for bands enabled on the node; combined = max(router, node). Wireless backhaul = `signal(router→node, backhaulBand, offset(backhaulBand))`; map hatches cells where node wins but backhaul < `backhaulThreshold`.
Calibration (per band): residual_i = measured_i − rawSignal(baseline→point_i, band); offset = median; report `rms` = sqrt(mean((residual−offset)²)). With no points → 0.
Coverage = share of **floor area** (cells) with signal ≥ `model.threshold`; "Celý byt" = all rooms not in `goal.excluded`, area-weighted.
Speed model & optimizer: port from old `monotoneSpeed / prepareSpeedCurve / rateAtSignal / predictSpeed / speedCandidateScore` (old file lines ~691–754) with the same constraints (needs ≥2 distinct signal values ≥ 5 dB apart; ↓ and ↑ for the same device+band; second node ⇒ speed unsupported; reserve %, wan limits, link limit).

### 7.1 Band-dependent obstacle loss (user: "the 2.4 GHz range advantage looks far too small")
Verified sources: NIST 1997 via wifivitae.com (brick 6/15/15 dB, 102 mm concrete 15/22/25 dB at 2.4/5/6 GHz), ursamajorlab.com

(5150–5350) / 30 dBm (5470–5725), 6 GHz LPI 23 dBm.
- Every obstacle loss value stored in a plan (wall.loss, door.loss, furniture.loss, model.wallLoss) is defined as the **5 GHz reference**.
  The model multiplies it by a band factor `k = {2.4: 0.65, 5: 1, 6: 1.15}` (engine constant, documented, tested). Existing files keep their

  is a preset uses the table; walls with material `custom` (or legacy values that differ from the old preset numbers) use their stored loss × k.
  Legacy walls whose stored loss equals the OLD preset value of their material (drywall 3, brick 8, concrete 12, reinforced 18, glass 3, wood 3,
  metal 25, masonry 8, solid_guess 12) are treated as that preset (new table). Furniture kinds get per-band values too (bed 1/1/1, wood 2/3/4,
